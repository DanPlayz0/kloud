## Support boundaries

- The control-plane runtime broker remains process-local: use a single API instance.
- Blue/green rejects incompatible host ports/namespaces, exclusive writable volumes,
  fixed addresses and unsupported discovery/overlap conditions instead of silently
  using downtime. Selected Compose services are release-specific; shared dependency
  restarts are explicit and may interrupt the app.
- PostgreSQL support is pinned to the version documented in
  [POSTGRESQL_RECOVERY.md](POSTGRESQL_RECOVERY.md). Import limits, staging quotas and
  archive/client/extension checks are enforced. A logical backup is not PITR.
- Source/provider/registry credentials are never a substitute for app deployment
  permission. Supplied Dockerfiles remain trusted code and can deliberately reveal
  secrets; output redaction is not an arbitrary-code confidentiality boundary.
- Public forwarding requires reviewed host networking and firewall configuration.
  Local tests do not prove preservation of real external source addresses on an
  arbitrary Docker host. PostgreSQL TLS is a separate blocked prerequisite.
- No buildpacks, templates, named environments/previews, MongoDB/ClickHouse
  management, separate build servers, multi-server replicas or Kloud-managed VPN
  enrollment are added by this work.

Do not advertise the combined A–F release or platform migration as accepted until
these external and unsupported-prerequisite gates have been resolved and verified.
